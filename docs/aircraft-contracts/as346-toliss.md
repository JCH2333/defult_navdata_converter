# AS346/ToLiss 加载契约

本文件保存 AS346/ToLiss 专用规则。它不属于默认通用数据 `NavModel` 的通用规则；使用前必须按 AIRAC、官方模板和当前 WASM 证据复核。

## 机场与跑道

- 已确认跑道查询形态为：`SELECT ... FROM tbl_pg_runways WHERE runway_length > 4757`，没有 `ORDER BY`。
- 加载器随后使用只向前移动的机场游标，因此 `tbl_pg_runways` 必须按物理行顺序排列为 `airport_identifier, runway_identifier`；新增跑道不能简单追加到表尾。
- 只有至少存在一条长度大于 4757 英尺跑道的机场才进入 AS346 可检索机场集合。

## 固定字段与容量

- NDB `magnetic_variation` 不得为 NULL。
- 航路点、航路标识和固定字段必须满足目标缓冲区长度与非 NULL 约束；距离、负数、枚举和数组索引必须在合理范围内。

## RF 航段

- `arc_radius` 必须为正数。Fenix 原始行通常提供弧心、上一航点、终点和转向，需要计算半径和弧长。
- 半径使用弧心到终点的大圆距离，单位海里；弧长使用平均半径乘以按转向确定的圆心角，单位海里。
- 转向缺失时只能在起终点和弧心足以确定的情况下选择较短圆弧并补出转向；无法确定时拒绝输出无效 RF。

## 程序分段

- 转换必须按 Terminal、route type、transition 分段，并在段内重新生成连续 `seqno`。
- Fenix 可能存在除 ID 外完全相同的连续程序行；写入前必须去重，避免产生零长度 RF。
- 公共程序段以 RF 开始时，只有前置跑道过渡终点完全一致才能继承共享终点作为 RF 起点。

## 验证要求

- 必须同时验证 schema、物理行顺序、NULL/长度/枚举/距离约束、机场检索、程序选择和退出飞行稳定性。
- 这些规则不能直接迁移到默认 BGL adapter；默认格式仍须使用自己的 XML/BGL 目标契约和 fixture。
